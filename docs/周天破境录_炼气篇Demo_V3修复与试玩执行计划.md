## 2. V3 玩法规则

### 2.1 阵眼、术语与基础规则

- 玩家看见“第一眼 · 入气、第二眼、第三眼、第四眼”，对应引擎 `slotIdx` 0–3。阵面常驻一个顺时针方向提示。真实起点为第一眼，释放会终止当前能量束。多个能量束可以分别在释放阵眼结算。
- 初期、中期、巅峰单回合破障阈值保持 `30 / 60 / 120`，基础消耗保持 `10 / 15 / 25`，初始真气 `100`。破障比较本轮产气，生存比较当前气池与有效费用。两组数值在 UI 中明确标名。
- 保留现有“上一道实际触发的道韵”触发连携的语义。空槽只传导，保留上一道类型。子束继承分裂瞬间已有的道韵记录，父束继续记录刚触发的分光。补文字与测试，把此决定从隐含行为变成可查规则。
- 运转仍由引擎单次执行，所有显示分数都读取实际结果。下表只是回归样例。获得战利品、布阵和付费使用真实手牌与气池。

### 2.2 初期教会玩家形成第一次释放

- 首局手牌为一张 LV1 聚灵和一张 LV1 灵爆。两张由玩家亲手放下。推荐第二眼放聚灵、第四眼放灵爆，第一眼与第三眼预留给中期。牌和阵眼同时高亮，提示在完成对应操作后消退。
- 初期达标前，允许从已占用阵眼将这两张开局牌收回手牌，无燃料消耗。该动作在阵眼菜单明确标为“收回道韵”，只对本局的两张开局牌在初期生效，避免放错顺序后因手牌为空无法调整。真实运转仍扣真气。达标后的布阵按原燃料规则处理。
- 第一次建议布阵的真实产气为 `43`。显示“聚灵增加基础气 → 灵爆结算”。V3 把分裂放到中期的构筑选择，初期只需要看懂一次完整传导和释放。
- 第一次空阵、没有可达释放或灵爆放得太早时，给一条可执行提示。零产气会按规则扣费并显示原因。玩家仍可运转。

### 2.3 中期提供一次可比较的选择

- 初期达标弹窗展示分光与锋芒两张已知候选，各有一句位置建议。分光建议放第一眼，锋芒建议放第三眼。只领取所选的一张，另发一张 LV1 聚灵作为机动手牌，可用于布阵或按照原规则作为一次移位的燃料。弹窗打开期间，下一轮运转与改阵暂停。选择只发一次，重复点击和跳过动画也只确认一次。
- 预留槽位上的选择可以直接落牌，无需覆盖和燃料。提前把灵爆放在前槽的玩家，可用机动聚灵将灵爆移到末槽，再放入刚选的牌。执行阶段要验证这种偏离推荐的路线仍然走得通。
- 分光的学习成果是能指出新增那束能量从哪里出现。锋芒的学习成果是能指出倍率在哪一步增长。达标后保留玩家阵面，进入巅峰时发放本局中期未选的那张牌和一张 LV1 万剑诀。保留现有聚灵机动牌的玩家，此时也能支付一次覆盖费用。

### 2.4 巅峰预告天劫，再让玩家作决定

- 页面会话内首次圆满前，巅峰固定为玄黄祥云劫，前两次运转费用为 `0`。进入巅峰就说明“前两次运转免费”，HUD 对应显示 `0`。使用次数耗尽后按巅峰运转次数计费，第三次的正常费用为 `145`。该局中途重开仍可重新走同一条教学路线。
- 首次圆满后，使用“再修一局”进入天劫随机的重玩流程。起手和已验证的关间奖励仍用这套配置。实际天劫进入巅峰时确定，随机重玩允许出现原阵直接过关的情形，例如心魔劫加强释放。刷新页面开启新的会话，首局教学资格随之重置。
- 两条推荐中期盘面在祥云劫下，即使该盘面出现额外分裂或暴击，也低于 `120`。玩家可以补上另一张组合牌，同样利用已有空位越过阈值；也可以用万剑诀测试剩余步数与更靠前的释放位置。
- 巅峰达标直接进入圆满终局。Demo 终局奖励使用结算页呈现，无须往已经结束的局内发看不见的材料。九霄神雷在 Demo 的说明保留实际会发生的耗气加速，共用配置及完整模式仍测试战利品翻倍。

- 在执行 `executeDemoTurn()` 前取本轮境界、小阶段、目标、气池、已经生效的天劫和有效费用。一轮上下文贯穿日志、回放、结果摘要、胜负弹窗和埋点。建议用现有返回结果加一个轻量上下文字段，或者入口保留明确快照。阵盘在播放期间锁定，用于呈现的路径直接来自结果日志。

### 3.3 取消、跳过与音频

- 每次播放有独立的取消身份，推荐用 `AbortController` 或等价的单次播放标记。调度器启动新播放时生成新身份。旧回调在每次等待恢复后，以及修改 DOM、播放音效或触发结算前，检查自己的身份与取消状态。
- 等待取消时可直接结束该分镜。`跳过` 显示引擎最终结果、清空临时画面并完成一次结算。`重修` 彻底作废旧局回调、关闭旧弹层和抽屉、清除操作态及结果数字，随后渲染新局。重开流程绝不能从旧局进到新局后再执行旧 `onComplete`。
- 为轨道亮光、浮字、震屏、光茧、经脉和延迟音效提供与当前播放一致的清理入口。可随阶段停止或淡出当前回合的合成音。音频初始化失败与浏览器拒绝播放都应让视觉和结算继续。开关初始状态读取已保存的静音值，静音后未播放的音符取消。
- 背景页恢复策略固定为“已开始的回合直接收束到真实结果”。用 `visibilitychange` 取消剩余演出，并保证返回时至多显示一个结果弹层。切前后台不会额外扣费、重发奖励或开启声音。

**阶段验收**

- 条件齐备时一次运转只扣一次、奖一次、弹一次。快速双击只有一次引擎调用。首关日志显示目标 `30`，进入下一关 HUD 后才显示 `60`。
- 心魔劫 `312` 后重开，同阵在祥云劫 `156` 时，圆满页和本地统计均为 `156`。
- 祥云劫前两次实际运行均免费，未达标时第三次显示并扣 `145`。神雷前三次应付值为 `25 / 87 / 181`。有足够真气时实付等于预告。费用不足时展示清楚的失败信息。

## 4. 阶段 2 · 使演出匹配真实流路

### 4.1 最小化补充结构化事件

优先修改 `src/types.ts`、`src/engine.ts`、`src/animationQueue.ts`。保留 `seq`、`pulseId`、位置、`detail` 和现有 `qiDelta` 供日志和兼容测试使用。

- 移动事件附真实起点和终点，包含环与槽。合并或绘制轨道按实际起终点和 `pulseId` 操作，避免所有能量束共用一个上一位置。Demo 只消费内环路径，识别不了的事件仍可写进调试日志。
- 分裂事件含真实生成的子束 ID 和落点。保留分裂上限，`spawned = 0` 时不显示新光束。母束与子束的状态用同一条结构化事件表达，UI 不按概率自己补分裂。
- 聚灵、锋芒、连携和 TTL 消散按实际类型播放。附能解释该次变化的最少数值字段，例如基础气增量、倍率增量和暴击倍数。无暴击的锋芒只显示倍率上升，失败或消散只播衰减反馈。中文 `detail` 保留给诊断，禁止用字符串查找推导逻辑。
- 释放列表按实际 `qiDelta` 累加，最后核对其和等于 `turnQiGenerated`。每束实际释放可保留在本回合明细，即使多数同类事件在主舞台被合并。最终数字与详细事件一致是回放的放行条件。

### 4.2 播放预算

- 普通演出建议首个有效移动约 0.2 秒，首个有效分裂或增幅单独停顿一次，最终释放给一次清楚的数字定格。常规段默认目标 `2–3 秒`，前台可见时从点击运转到该轮常规演出结束的预算上限 `3.2 秒`，小突破单独约 `0.8 秒`。按现有配置集中管理这些时长。
- 默认先播首次分裂或增幅、关键路径和首次释放。后续重复轨道缩短或并播，相同出口的后续释放汇总成实际次数和实际增量。生成简化事件序列时保留先后关系；尾段合并对玩家显示为“后续 N 束合计 +X”。零释放、零日志和到达 Tick 上限时直接给可读反馈。
- 回归压力盘面为四张分光。在当前规则与 `rng = 0.4` 下达到 `2,000 Tick / 7,964 条日志`，原队列按全部等待推算约 24 分钟。引擎可继续保留诊断日志，DOM 抽屉只渲染当前回合的有限条目，截断时标明其余条数。回放靠时长预算收口。连续传导补寿命以现有引擎规则作回归基线，将来若调整触发次数，另行验证数值。
- 低运动模式采用相同结果和轨迹数据，保留短静态高亮、真实构成和胜负反馈。普通段目标不超过 `1.2 秒`，终局简化到约 `0.8 秒`。跳过在普通和终局都按同一清理规则立即完成，区别于自主选择播放的低运动模式。

### 4.3 圆满分镜

完整动画仅在炼气巅峰真实达标时播放，显示“炼气圆满”，不解锁外环。正常观看按现有时长配置播放以下分镜，总计约 `4.5 秒`。小关只给丹田短亮与突破提示。

| 时间 | 主舞台动作 |
| --- | --- |
| 0–0.7 秒 | 从本轮真实释放阵眼保留青色余辉，接一束金色向心光，汇入丹田 |
| 0.7–1.5 秒 | 金光沿几条经脉从丹田依次点亮，修士轮廓变清楚 |
| 1.5–2.3 秒 | 先出现薄金光茧，再短暂收紧、显出裂纹 |
| 2.3–3.2 秒 | 冲击波由修士向外扩散，四个阵眼可以共同象征性响应 |
| 3.2–4.5 秒 | 圆满字样入场并定格，接上本局结算按钮 |

**阶段验收**

- 固定四卡灵爆样例能识别两束各沿引擎槽号 `1→2` 和 `2→3` 到达，同一次回放出现两次真实释放，每次 `78`，普通锋芒无暴击字样。补测额外分裂、有暴击、分裂上限、过期和零产气。
- 回放按引擎移动日志抽查轨道，不存在凭局部上一帧推断的假路径。只走部分槽位的巅峰测试里，向心来源来自本轮的真实释放点，金色经脉作为象征演出与青色计分轨迹可区分。
- 默认、四分光压力、低运动和不同节点跳过都用浏览器时钟或等效可测工具记录时长。普通与终局时长分开测。切回页面时显示与一次真实结算一致的结果。

## 5. 阶段 3 · 布阵与移动端交互

- 以当前 `ActionState` 收紧合法输入。等待覆盖燃料时，空槽和其他目标槽不能消耗待放牌，手牌中只有合法燃料可确认。等待拆除或移位燃料时可选燃料或取消。选择移位目标时只接受空槽。满盘时直接标明没有空槽可移，覆盖仍按现有规则执行。运转与结果弹窗期间只开放明确可用的操作。
- 提示条显示目标阵眼、待放牌和实际消耗。选择无效目标、燃料不足、手牌为空、重复选中同一卡等失败原因都在主舞台附近可见。纯覆盖写清旧道韵与燃料都会消耗。保留已经放置的牌的说明入口。
- 布阵页用原生按钮承载手牌和阵眼，保留焦点和选中反馈。重绘后把焦点回到对应的牌或阵眼，避免键盘用户从头导航。结果或阵眼菜单用原生 `dialog`，打开时聚焦内部，关闭后返回触发点。关闭的调试抽屉移出 Tab 序列，图标按钮提供可读名称，状态变化用适度的状态公告。
- 调整 `src/style.css` 的阵盘尺寸，使其同时受可用宽度、高度约束。提示区预留稳定空间，低高度允许纵向滚动。手牌较多时仍可横滑。移除强制禁止页面缩放的视口设置。主要阵眼与操作触控区域以约 `44 × 44 CSS px` 为规划目标，提示和浮字不挡点击。
- 一次运转失败后显示三项中的必要信息：实际产气、剩余气池、下次有效费用。如无可达释放，用规则化提示指出原因。避免把玩家可恢复的低产气和已经耗尽的终局混成一个提示。

**阶段验收**

- 选牌进入覆盖后点空槽，手牌、待覆盖牌和两个槽位均无意外变化。取消无成本。合法覆盖、拆除、移位各验证一次准确耗牌，留一条非法输入不改状态的回归。
- 空槽先点后选牌、燃料不足、释放放得太早都有可见提示。空阵的原压力样例在费用未改时为气池 `100 → 90 → 60 → 2`，第四次无法支付 `92`。从失败弹窗可重开。
- 在 `320×568`、`360×640`、`390×844`、`667×375` 和常见桌面视口下，选中长说明道韵后定位并点击四个槽。先检查实际命中元素或真实 pointer 操作，再检查横向手牌、按钮和结算弹层，几何边界单独通过不足以签收。
- 只用 Tab、Enter、Space、Esc 能完成选牌、落牌、取消、在弹层内继续、关闭抽屉。键盘焦点在任何状态都能看见。

## 6. 阶段 4 · 按规则接入玩法内容

- 将第 2 节的 Demo 境界上限、起手 ID、关间候选、机动牌、固定天劫和时长集中进入 `src/demoConfig.ts`。让实际创建和规则调用读取这组配置，删除 `game.ts` 里的重复清单及未被任何流程使用的节拍项。
- 在现有 Demo 入口注入最少可选规则。初期奖励与中期二选一用一个待领取状态和一个领取入口。小关推进可以由引擎一次完成，但玩家确认后才开放下一轮输入。随机正式掉落仍由 `executeTurn()` 默认路径发放。
- 在 `main.ts` 用阶段与现有槽位判断软引导，避免新增教程路由。显示建议槽位、放牌作用和一个下一步。仅在初期的两张开局牌上开放收回，转移保持同一牌实例。非开局卡、过关后和演出中走原布阵规则。
- Demo 掉落按第 2 节的显式清单出牌。逆流、依赖升环的周天，以及本期没有要演示其跃迁作用的升维从这条掉落路径移出。保留全道韵配置。配合更新玩家看到的卡牌短说明。
- 先用外显的固定教学天劫跑通，再验证另外两种天劫下的费用、TTL 和释放倍率。重玩随机天劫继续用项目实际 RNG。随机天劫发生时，试玩日志能区分各天劫下同一盘面的变化。

**阶段验收**

- 从空阵开局跑两条独立路线，中期分别选择分光、锋芒。两条路线都有首关构筑结果且中期超过 `60`；不改中期建议阵时巅峰祥云劫达不到 `120`。选错牌或偏离推荐位置时，仍能理解提示并用现有动作修正。
- 特别测“第一眼聚灵、第二眼灵爆”。它可过初期，进入中期后领一张分支牌和一张机动聚灵，用聚灵作燃料把灵爆移到第四眼，再放所选分支。分别验证两种分支都能过中期。
- 将释放放在聚灵之前，故意跑出低分，收回并按推荐重放能继续。转入中期后确认同两个阵眼仍按正常成本调整。
- 跳过、重复事件与重复点击不会拿到两张二选一牌。领取前不能运转。巅峰只显示“炼气圆满”，按钮重开可见，完整演出只播放一次。
- 重玩覆盖三种天劫。默认完整模式仍从炼气推进筑基、解锁外环、走原掉落及灵宝行为。

### 8.3 五人观察式试玩

先用同一个生产版本和首次祥云劫教学路径跑 5 人。观察者不提前解释玩法，记下实际操作、停顿点及玩家复述。每人先完成独立试玩，再让他解释一道实际发生过的现象。建议观察目标如下。

| 观察项 | 第一轮目标 |
| --- | --- |
| 30 秒内布出有效阵 | 至少 3/5 |
| 60 秒内看到真实释放 | 至少 4/5 |
| 能说出分光、锋芒或位置改变了什么 | 至少 3/5 |
| 看过圆满后，能讲出哪处释放为修士入体供气 | 至少 3/5 看过演出的人，单列分母 |
| 主动改变至少一个阵眼或重开试另一套 | 至少 2/5 |

把观察记录写成“发生了什么、玩家怎么解释、哪个改动能验证”。首轮修复顺序为先解决不能操作，再解决看不懂，最后调整爆发强度。从具体行为与叙述定位问题，五人的比例只用于该版本的迭代判断。
