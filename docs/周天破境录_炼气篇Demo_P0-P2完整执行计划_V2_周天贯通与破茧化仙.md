# 《周天破境录：炼气篇》Demo 执行计划（P0 / P1 / P2）

> **用途**：直接交给本地 AI 在现有代码仓库执行。  
> **版本**：V2.0（周天贯通 × 破茧化仙融合版）/ 2026-11-19  
> **首要目标**：只展示“炼气期”，在 2～5 分钟内，让玩家清楚体验 **摆阵 → 灵气沿阵运行 → 分裂/增幅 → 数字爆发 → 周天贯通、修士觉醒 → 炼气圆满/重试**。  
> **开发原则**：最小改动，保留核心引擎，先交付可玩、可看、可测的 Demo，不建设未来系统。**本版最重要新增项是炼气圆满的联合破境演出**：玩家的阵法之力经由真实连线汇聚至阵心，进入打坐修士体内，点亮经脉，最后由修士与法阵共同完成破境；修士仅为演出视觉主体，不增加可操作角色系统。

---

## 0. 当前项目基线（已核对上传代码）

- 技术：原生 TypeScript + Vite + DOM + CSS，已有 Vitest 测试；**不需要引入 React、Vue 或游戏引擎**。
- 现有入口：`index.html`、`src/main.ts`、`src/style.css`。目前为“核心数值引擎调试台”，主要以文字槽位与日志呈现。
- 现有玩法逻辑：`src/game.ts` 提供 `createInitialGameState()`、`placeDao()`、`executeTurn()` 等；`src/engine.ts` 负责能量束结算。应优先复用。
- 已有事件来源：`executeTurn(state)` 返回 `simulation.logs`，含 `seq`、`pulseId`、`ringIdx`、`slotIdx`、`action`、`detail`、可选 `qiDelta`。**可作为演出数据基础**，不应让动画自己重新算分。
- 当前棋盘：`src/data/board.json` 配置五环槽位 `[4, 6, 8, 10, 12]`，但初始只解锁第 0 环（4 槽）。
- 当前境界：`src/data/stages.json` 含 15 个小关；炼气是 `realm=1, subStage=1/2/3`，阈值分别为 `30 / 60 / 120`。
- 现有道韵：8 种，其中适合首轮连锁演示的有：分光道韵（`dao_chain`）、聚灵道韵（`dao_gather`）、锋芒道韵（`dao_crit`）、灵爆术（`dao_burst`）。
- **特别注意**：现有规则在炼气巅峰通关后会进入筑基并解锁新环；Demo 必须在此节点拦截并结束，而不是靠删除全部高境界数据避免进入。

## 1. 明确做什么、不做什么

### 本期只做

1. **一个炼气场景**：入口至结束只展示“炼气初期 → 中期 → 巅峰 → 炼气圆满”。
2. **一个核心阵盘**：只显示当前可用的 4 槽内环，做成视觉完整的圆形法阵；不伪造第二环的真实玩法。
3. **一条核心体验**：选卡、点槽位布阵、运转周天、观看路径与增幅、获得结果、调整/再来。
4. **两层高潮**：常规回合看见真实连锁产生更大释放值；炼气巅峰通关看见“阵盘贯通 → 灵气入体 → 经脉觉醒 → 周天爆发 → 炼气圆满”的终局演出。
5. **一个试玩入口**：电脑浏览器和手机竖屏浏览器均能独立使用，网页可部署分享。

### 本期明确不做

- 筑基及更高境界、15 关完整内容、微信小游戏正式接入。
- 新战斗系统、新怪物、**可操作角色/角色成长系统**、账号、广告、支付、联网排行榜、服务器。**允许在阵心加入一个仅供演出的静态打坐修士剪影**。
- 复杂天赋树、局外成长、成批新增卡牌、经济平衡大改。
- 完整重写 `engine.ts` / `game.ts`，为了特效引入复杂粒子引擎。
- 视觉上刻意制造与实际结算不一致的“假连线”“假倍率”“假分数”。允许纯象征性特效（经脉点亮、光环、冲击波），但不能把它们显示为真实计算事件。

### 唯一产品判断标准

> 试玩者能看懂“气从哪里来、经过哪里、为什么放大、在哪里释放”，并愿意主动换一种摆法再试一次。

| 阶段 | 交付目标 | 放行条件 |
| --- | --- | --- |
| **P0 · 可玩闭环** | 炼气单境界、主舞台、基本交互、首局教学、正确结算 | 能独立完成一次炼气体验；无筑基跳转；构建与测试通过 |

# P1 · 氛围、连线与数字爆发（本项目最重要的体验阶段）

## P1-01｜统一美术方向：一座洞府、一面法阵

- [ ] 视觉风格确定为：**暗色洞府 / 青青灵雾 / 少量金色符纹 / 温润玉石阵眼**。避免赛博仪表盘、过度霓虹。
- [ ] 层级：背景最弱、阵盘及节点最强、总爆发数字是瞬间视觉焦点。
- [ ] 背景允许静态插画、CSS 渐变与简单纹理；禁止为背景引入高成本 3D 场景。
- [ ] 阵盘添加细圆环、符文刻线、中心聚气点；**阵心安置一位打坐修士的半身或全身剪影**（建议使用简洁 SVG/透明 2D 素材，不做复杂角色动画）。修士必须在视觉中心但不遮挡真实四槽阵眼、路径与数字；未运转时只保留柔和丹田微光。
- [ ] 已放道韵按类别区分颜色/图形（传导青、增幅紫金、释放金红等），并通过文字辅助辨认。
- [ ] **轻度氛围动画**：微弱灵雾/慢速呼吸光；普通状态不能闪烁抢眼。打坐修士的剪影是唯一人物元素：不做走动、战斗、换装、数值成长。

**验收**：不用看标题，仅看首屏截图就能识别“修仙法阵”主题；阵眼和可点击操作依然清楚。

## P1-02｜构建基于真实日志的“演出队列”

- [ ] 仍由 `executeTurn(state)` **一次性完成真实结算**，得到 `simulation.logs` 和结果；随后按事件顺序播放动画，**不重复运算、不二次改状态**。
- [ ] 原有日志含 `pulseId`、`seq`、`action`、`ringIdx/slotIdx`、`qiDelta`。用这些先制作轻量事件映射。
- [ ] 对 `MOVE` / `OUTER_LOOP`、`CHAIN_SPLIT`、`AMPLIFY`、`RELEASE`、`EXPIRE`、`SYNERGY` 做映射；没有对应 UI 的其他事件至少要安全跳过。
- [ ] 对于日志中“移动后的坐标”和“当前节点坐标”要准确辨别，必要时只给核心动画补最小的结构化轨迹字段；**不要解析中文 `detail` 字符串来反推真实数值或路径**。
- [ ] 每次回合执行前保存**前态快照**（至少 `realm/subStage`、当前盘面、上一轮产气），在 `executeTurn()` 返回后利用 `cleared` 和前态判断是否触发初/中/巅峰突破；引擎会同步修改状态，UI 必须先播该回合真实日志，再播破境演出，最后切换下一阶段的可见状态。
- [ ] 处理同一 `pulseId` 的连续位置；分裂出来的新 `pulseId` 显示为新光点/光流。
- [ ] 高事件量时进行演出压缩，避免一轮要播十几秒；可提供“跳过动画”而不影响实际结果。

**验收**：动画序列与实际模拟事件类型、阵眼位置、最终产气一致；多分裂时不乱线、不漏结算。

## P1-03｜设计 2～3 秒“聚气—传导—增幅—爆发”节奏

- [ ] 默认流程分为 4 拍：**聚气（约 0.2～0.4s）→ 传导（约 0.5～0.9s）→ 连锁增幅（约 0.4～0.9s）→ 释放（约 0.3～0.6s）**。
- [ ] 用一个亮点从阵盘中心启动，随后沿顺时针槽位之间的真实路径运行。
- [ ] 走过的线短暂高亮，终止后逐步衰减；不能整盘同时常亮。
- [ ] 分裂事件：一束变多束，视觉上能看懂“数量变多”，并出现简短提示“分裂 +1”。
- [ ] 增幅事件：该阵眼亮一下，并显示 `+基础气`、`+倍率` 或 `暴击×...`；内容必须来自真实事件/结构化数据。
- [ ] 释放事件：能量束收束到释放阵眼，形成一次明显的瞬时爆发。
- [ ] 如果一轮中很多能量束轮流释放，按真实释放次数聚合视觉节奏；不要让玩家等待每个重复细节。

**验收**：观众看一遍无需日志，就能指出“哪里分裂、哪里变强、哪里最终释放”。

## P1-04｜数字爆发必须形成强弱对比

- [ ] 运行中：节点边显示小数字/倍率，字体不遮挡阵盘。
- [ ] 释放瞬间：屏幕焦点位置出现**本轮产气最终总值**，字体放大、短暂定格、发光消退。
- [ ] 若有多次释放：展示真实的单次 `qiDelta` 递增，最后收束成真实总值；不要在动画中插入虚构分数。
- [ ] 记录**上一轮的真实产气**，下一轮结算显示 `本轮 X`、`上轮 Y`、`提升 +Z%`。上轮为 0 时改为“首次爆发”，避免除零。
- [ ] 比上轮更低时也必须如实显示；不能只有涨幅，不显示下降。
- [ ] 爆发效果采用**放大、停顿、光晕、短促轻震屏（可选）**，控制在舒适范围，不持续震屏。

**验收**：玩家一眼知道最终“爆了多少”，并知道第二次布阵是否比上次更强。

## P1-05｜“周天贯通 × 破茧化仙”联合破境演出（最高优先级的新增任务）

### A. 统一设计：不是播放一段无关过场，而是**玩家亲手布置的法阵让修士完成突破**

- [ ] 采用同一主舞台：**外圈保留四个真实阵眼、真实能量路线；阵心是盘坐修士的二维剪影**。不突然切换到与游戏无关的全屏 CG。
- [ ] **先结算、再演出、最后展示结果**：`executeTurn()` 仍是唯一计算来源；真实 `simulation.logs` 负责阵盘的前半段能量运行；破境阶段追加纯视觉的“阵心汇聚、丹田入气、经脉觉醒、周天冲击波”。
- [ ] 小阶段（炼气初期→中期、中期→巅峰）只用 **0.6～1.2 秒轻量反馈**：法阵短暂贯通、修士丹田光增强、境界文字出现。**不要提前使用完整人物觉醒与冲击波**，保留终局的对比。
- [ ] 仅在**炼气巅峰真实达标**时触发下面的完整 4～5 秒演出；没有过关不能触发。触发需一次性锁定，不能因重复渲染/点击而重播。

### B. 终局 4.5 秒分镜（从该回合真实运转动画播放完毕后开始计时）

| 时间 | 画面/运动 | 给玩家的感受 | 最小实现方法 |
| --- | --- | --- | --- |
| **0.0～0.7s｜周天归一** | 最近完成运转的阵眼沿**真实有效路径**依次余辉亮起；已有光点和光流向中央丹田位置收束，背景亮度略降 | “刚才那套阵真的打通了” | 复用本轮高亮路径与 SVG 线层，加 1 条向中心的**象征性汇聚光**；不要标注虚构倍率 |
| **0.7～1.5s｜灵气入体** | 阵心打坐修士的丹田从青光变金光，身体轮廓轻微发亮；3～5 条简洁的经脉光纹由丹田向胸腹、双臂依次点亮 | “阵法力量进入修士体内” | 单张修士剪影 + 覆盖 SVG 经脉路径，通过 CSS/SMIL 或 `stroke-dashoffset` 点亮；不做骨骼动画 |
| **1.5～2.3s｜破茧冲关** | 人物外出现薄金色光茧/气罩，先收缩停顿约 0.15s，再出现裂纹与强光；法阵同步震动一次 | “力量突破瓶颈” | 半透明椭圆光茧 + 4～8 条预设裂纹路径 + 1 次短促缩放/闪光，禁止持续震屏 |
| **2.3～3.2s｜周天贯通** | 人物金光向外扩散成环形冲击波，穿过四个阵眼；盘面符文依次金亮，人物气息稳定 | “修士和法阵同时完成蜕变” | 1～2 层 SVG/CSS 同心扩散圈、阵眼逐个激活；完全不改变真实数值和槽位 |
| **3.2～4.5s｜炼气圆满** | 亮度回落，打坐修士保留温和护体光环；阵盘成为完整金色周天；中央浮现“炼气圆满”，接着显示真实最高爆发值和“再修一局” | “值得停下来欣赏的成就时刻” | 简单 CSS 文字入场 + 结果层；**不强制要求做角色睁眼、悬浮、换装或额外 3D 场景** |

> **分镜术语约定**：“真实有效路径”只表示本轮日志实际经过的道韵/移动关系；“光芒从阵盘进入修士经脉”“冲击波穿过阵眼”是**破境象征效果**，并非引擎新增的能量路径或数值事件。两者要通过不同颜色/线型或运动样式区分，避免玩家误以为产生了新的计分事件。

### C. 视觉层与空间关系

- [ ] **视觉从后到前**：洞府/灵雾背景 → 圆形法阵纹样 → 真实阵眼/连线 → 阵心打坐修士 → 经脉/丹田亮光 → 破境光茧/冲击波 → 结果文字。具体层级可按点击需求调整 `pointer-events`，但不能挡住阵眼。
- [ ] 修士推荐采用**无面部细节、盘膝静坐、衣袍轮廓清楚**的低成本二维剪影；常态占阵盘内径约 20%～30%，与真实四槽位置留出安全间距。若移动端拥挤，优先缩小人物，而不是压缩阵眼点击区。
- [ ] 色彩分阶段：常态青色冷光 → 经脉暖金 → 冲关白金短闪 → 圆满温金。禁止常态一片金黄，确保最终有明显前后对比。
- [ ] 平时不让修士抢占视觉焦点；**直到炼气巅峰通关时**才让人物与外圈阵盘同时成为主视觉。终局效果完成后仍要让玩家看到原本自己布置的卡牌，而非完全被过场替换。
- [ ] UI 可以在破境开始时暂时淡出手牌和次要指标，结束后恢复“最高爆发值 / 炼气圆满 / 再修一局”三个可识别焦点。

### D. 播放控制、可达性和真实性

- [ ] 完整破境动画与原有回合演出使用**同一个串行队列**：回合模拟 → 真实路径演出 → 终局破境 → 圆满结果；禁止另一套计时器独立改写状态。
- [ ] 开始播放后禁止重复触发“运转”，但保留**跳过**；跳过必须直接进入相同的正确结算页，绝不漏结算或重复发奖励。
- [ ] 手动重开或切走时及时清理动画/异步回调；避免旧局人物“继续破境”覆盖新局界面。
- [ ] `prefers-reduced-motion` 模式压缩成 **0.5～1 秒的低运动版本**：经脉逐渐点亮 + 最终圆满定格；避免强闪和震屏，并保留完整的胜利信息。
- [ ] 若缺失剪影素材、设备性能不足、音频不可用，则退化为**阵盘贯通 + 中央剪影明暗变换 + 圆满文字**；不能卡死或空白。

### E. 明确验收条件（本任务必须逐项通过）

- [ ] **条件 1：因果清楚**。第一次看的人能够说出“我摆的阵把气引到修士身上，修士突破了”，而不是“系统突然放了个动画”。
- [ ] **条件 2：阶段有差别**。初/中小突破只点亮阵心，巅峰通关才有完整经脉觉醒、破茧与金色冲击波。
- [ ] **条件 3：数字真实**。演出前后 `simulation.turnQiGenerated`、最高单轮产气、通关状态一致，不能在画面里伪造增幅或奖励。
- [ ] **条件 4：时间受控**。普通运转仍约 2～3 秒，最终额外破境约 4～5 秒；可以跳过，播放期间无重复结算。
- [ ] **条件 5：视觉可读**。手机竖屏中阵眼、人物、经脉、结果不互相遮挡；无持续过曝、卡顿或高频闪光。
- [ ] **条件 6：可交付演示**。提交一段涵盖“真实连锁 → 数值爆发 → 灵气入体 → 经脉亮起 → 破茧 → 炼气圆满”的完整录屏，或按 5 个关键节点的截图组证明执行结果。

**P1-05 完成标志**：终局视觉不只是一个大字/光效，而是让玩家看见“阵法周天贯通，力量入体，修士完成炼气圆满”的完整过程；同时不增加可操作角色系统，也不修改游戏的核心计分规则。

## P1-06｜音效与性能底线

- [ ] 优先用少量音效完成“聚气、节点触发、最终释放、破境”四类反馈。终局可沿用现有音色叠加 1 个低沉蓄力音 + 1 个短促破茧音 + 1 个清亮圆满音；音频可选，不能因素材缺失阻塞交付。
- [ ] 默认尊重浏览器音频播放限制，首个用户手势后再启用声音；提供静音开关。
- [ ] 支持 `prefers-reduced-motion`：弱化持续闪烁、震屏及过长特效；关键结果仍要清楚。
- [ ] 动画绘制建议继续使用**现有 DOM + CSS + SVG**：真实线路、修士剪影经脉、光茧裂纹、扩散冲击波都可用同一 SVG 舞台组织；不额外引入 Canvas/3D/粒子引擎，除非现状证明必要。
- [ ] 在主流手机浏览器上保证阵盘交互和数值动画基本流畅；高负载时可关闭非关键粒子而不是破坏结算。

**验收**：普通手机没有明显持续卡顿；音效失败或设备无音频也能正常完成全程。

## P1-07｜演出准确性与极端情况

- [ ] 点击运转到动画结束期间禁用重复运转；重开/切页/跳过时取消旧的待播演出，避免串局。
- [ ] 日志事件数为 0、未能释放、产气为 0、只有一次释放、多束并发、能量过期等场景可正常收束。
- [ ] 验证**只有巅峰真实通关**触发完整破境；初/中仅短反馈，失败/低产气绝不能播放圆满演出；重复点击、重开中断、主动跳过、窗口隐藏后恢复的结果必须一致。
- [ ] 对照同一回合日志与界面验证：**释放总和 = `simulation.turnQiGenerated`**。
- [ ] 高倍数/长数字能自适应缩小字体，不溢出主屏。

**P1 完成标志**：真实玩家能从普通运转中理解数字为何变大；到终局能清楚看到**灵气从真实阵盘汇聚、进入打坐修士、经脉点亮、破茧贯通并炼气圆满**，且对这两层高潮有明显区分。

| 文件 | 预期动作 | 约束 |

## 4. 技术与产品关键约束（防止本地 AI 做偏）

1. **“炼气一层”是一个境界，不是五环全部展开**。当前第 0 环有 4 个真实槽位。先把这 4 个槽位的连线视觉做美；若确实发现 4 槽不足以表达体验，再另提最小扩展方案，不能擅自重写多环算法。
2. **引擎是唯一数值真相**。画面可以延迟播结算动画，但不能让表现层重新模拟产生另一个数字。
3. **演出与回合不可重入**。模拟一次、演出一次、结算一次。动画中禁止二次运转；重开必须清除上一局的动画队列。
4. **第一局允许设计，但不允许造假**。固定牌组与固定随机种子可以，但显示的分裂/倍率/伤害必须真由引擎产生。
5. **先让玩家看懂，再增加更炫的效果**。如果粒子、背景妨碍看清路径，优先削弱装饰；如果人物妨碍四槽交互，优先缩小或降低人物亮度。
6. **不要牺牲可维护性换取表面效果**。只做本期必需的最少实现，不提前支持多境界、多主题、多端封装。
7. **当前代码使用“炼气”而非“练气”作境界名称**，游戏内统一沿用“炼气”。
8. **破茧化仙是演出概念，不是提前飞升**。最终文案必须是“炼气圆满”；修士可以经脉觉醒、光环护体，但不得显示飞升成仙、进入筑基或其他已禁用境界。
9. **每一帧要忠于玩家操作的因果**。法阵的有向亮线依据真实事件，聚气入体与经脉亮光是视觉象征；不能为了震撼把四个阵眼硬说成完整五大境界。

## 6. 最终人工验收脚本（项目负责人照做即可）

1. 手机打开 Demo，先不看说明：是否一眼感觉是“修仙法阵游戏”？
2. 选第一张牌并放阵眼：是否立即知道操作成功？
3. 补齐连锁关键节点，点击“运转周天”：能否看清路径和节点先后？
