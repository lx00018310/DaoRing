# 《周天破境录》斗法场景视觉方案

目标：参考《凡人修仙传》《仙逆》等国漫的斗法观感，把「阵盘算分」包装成「一场一场的斗法」：胜则晋升、获得道韵，败则身死道消。

## 1. 文件

| 路径 | 说明 |
| --- | --- |
| `prototype/battle/index.html` | 单文件可玩原型，浏览器直接打开。素材已内嵌，离线也能跑（书法字体走 Google Fonts，离线时回退楷体） |
| `public/assets/battle/bg_misty_peaks.jpg` | 云海群峰背景（1600 宽） |
| `public/assets/battle/hero_cultivator.webp` | 主角背身立绘（透明底） |
| `public/assets/battle/foe_demon_elder.webp` | 魔修长老立绘（透明底，按关卡变色复用） |
| `tests/battle_prototype.flow.js` | 全流程验证脚本：`node tests/battle_prototype.flow.js`，共 41 项 |

## 2. 画面分层（从后到前）

1. 背景画 + 视差（随鼠标偏移），上下压暗，把视觉焦点留给中景
2. 远雾（缓慢漂移的柔光雾团）+ 灵气光点
3. 敌人：血光、黑气粒子、随机血色雷光、悬浮呼吸；受击时闪白并击退
4. 阵盘：透视椭圆同心环 + 顺时针流动的阵纹虚线 + 中央丹田阵纹；阵眼是玉盘，有道韵时升起光柱、浮出符字（传导青 / 增幅金 / 释放赤）
5. 主角：呼吸、衣袂摆动、掌心聚光；被反击时泛红
6. 能量束（加色混合）：尾迹会随倍率由青转金，随基础气变大；分光时弧线跃出子束
7. 攻势：万剑诀是飞剑群沿贝塞尔弧线齐射；灵爆术是先蓄力，再以金色火球轰出
8. 粒子、冲击波、伤害数字、书法大字（斩 / 万剑诀 / 突破 / 身死道消）、全屏闪光、屏幕震动、破障瞬间慢放

## 3. 一回合的节奏

起手（0.8s）：扣修为，掌心光束注入第一眼 → 能量流转（按步数自动压缩到约 3 秒内）→ 遇释放道韵出招 → 命中结算：
- 单次产气 ≥ 护体魔光：慢放、破字闪光 → 「斩」→ 敌人碎成粒子 → 择一道韵奖励（另得 2 张）→ 下一敌入场
- 未破：护体回满，魔修以血雷反击；修为付不起下次运转即「身死道消」：画面转灰，主角化灰，弹出陨落结算

境界第 3 关通过后播放「突破」演出，展开外环。

## 4. 接入正式工程的建议

- 演出必须由引擎日志驱动，而不是由 UI 自己推算。原型里的 `simulate()` 已输出带 `t / pulseId / from / to / kind` 的结构化事件，与 V3 计划 §4.1 的要求一致。接入时把它换成 `src/engine.ts` 的真实日志即可，展示层不再保留第二套规则
- 渲染建议：保留现有 Vite + TS，渲染层换成 PixiJS（WebGL、加色混合、滤镜、粒子性能都更好）。角色动画用 Spine 或 Live2D 做骨骼呼吸、施法、受击、死亡四段
- 美术管线：背景按 远景 / 中景 / 近景 分层出图做视差；角色出透明底立绘，再加表情或动作差分；特效优先程序化，关键招式再补序列帧
- 原型为保证可玩，引擎规则做了简化移植（未含连携、天劫、法宝）。数值沿用 `stages.json`，筑基之后的平衡需要用真实引擎重新校准

## 5. 已知限制

- 敌人只有一张立绘，靠色相变化区分；正式版每个大境界至少需要 1 个专属敌人
- 立绘是静态图 + 程序化呼吸动画，还不是骨骼动画
- 移动端已做等比缩放，未做竖屏布局

## 6. 已接入正式游戏（v0.2）

斗法场景已作为**正式模式**接入工程，入口 `battle.html`（开发时 `npm run dev` 后访问 `/battle.html`；炼气篇教学关顶栏的 ⚔ 按钮、通关弹窗也可进入）。`index.html` 的炼气篇教学关保持不变。

| 文件 | 职责 |
| --- | --- |
| `battle.html` | 斗法页面骨架（HUD、阵眼点击层、手牌、弹窗） |
| `src/battle/session.ts` | 对局会话：调用 `executeTurn` 推进 15 场斗法，灵宝三选一、炼化、必死判定、功德结算 |
| `src/battle/timeline.ts` | 把引擎 `SimulationLogEntry` 转成演出时间轴（每股能量的路径、触发与释放） |
| `src/battle/scene.ts` | Canvas 渲染与特效（只负责「怎么画」） |
| `src/battle/main.ts` | 界面交互：布阵、覆盖 / 拆除 / 移位、回合演出编排 |
| `src/battle/geometry.ts` | 五环透视阵盘几何（40 个阵眼互不重叠） |
| `src/data/foes.json` | 15 个关卡的敌人名称、色相与体型 |
| `src/battle/battleConfig.ts` | 演出时长预算、开局保底 |
| `tests/battle.test.ts` | 时间轴 ↔ 引擎一致性、几何、整局流程测试 |

规则全部来自 `game.ts` / `engine.ts`，演出不再自带一套规则：

- 每次运转先由引擎结算，再按日志播放；每束释放的伤害就是该束 `RELEASE` 的 `qiDelta`，合计等于 `turnQiGenerated`。
- 演出期间 HUD 与手牌冻结在回合前，按「出手 → 斩敌 → 战利品 → 新敌」的顺序揭晓，不提前剧透。
- 炼气 → 化神共 15 场；大境界突破解锁外环、灵宝三选一；每个巅峰降天劫（神雷 / 心魔 / 祥云各有画面）。
- 打不破护体又付不起下次运转时判定必死，由引擎宣告走火入魔，播放身死道消；单局结束写入功德档案。
- 长回合超过约 3.4 秒的尾段合并为一次「后续 N 束合计」，可随时跳过；切到后台自动跳过。

模式差异：正式模式开局 6 张随机牌（必含灵爆），若既无聚灵也无升维，会把一张非灵爆牌换成 LV1 聚灵，避免开局打不过炼气初期 30 的门槛。

待办：筑基以后的数值曲线尚未用真实对局校准；敌人仍是一张立绘换色复用；竖屏手机上画面会很小，建议横屏。
